# Rust semantic-call ground truth

Independent ground truth for Rust call resolution on the three pinned repos in
`benchmarks/rust-repositories.json` (walkdir, mini-redis, ripgrep `crates/ignore`).

## Files

- `sample.json` - generated by `npx tsx benchmarks/rust-call-oracle.ts`. Deterministic: no timestamps or randomness; re-running yields a byte-identical file. Entries carry `repo,file,line,col,callerQualifiedName,callText,calleeName,category,split` and NO labels.
- `counts.json` - per-repo raw totals per category, plus `hiddenInMacro`. Also the extraction-coverage oracle.
- `<repo>.json` (later tasks) - labelled ground truth: the sample entries plus
  `expected: { kind: "resolved"|"external"|"unresolvable", target?: { file, qualifiedName, line, kind: "fn"|"method"|"assoc-fn"|"trait-method-decl"|"struct"|"enum-variant" }, confidence: "exact"|"probable", why }`.
  `resolved` = statically targets a definition inside the indexed scope (concrete type: the impl method; via generic bound / `dyn` / `impl Trait`: the trait method declaration, `probable`). `external` = std/dependency/prelude/other crate outside the sparse scope. `unresolvable` = exists only via macro expansion/derive/blanket impl.

## Independence rules

The oracle imports only `tree-sitter`, `tree-sitter-rust` and Node built-ins - nothing under `src/`. Labellers and the oracle must not run or import the indexer/adapter, and must not read `benchmarks/results/*`. Nothing under `src/` may mention this data set.

## Position

`line` is 1-based, `col` 0-based, both of the _callee-name token_ (method name, last path segment, bare identifier, macro name), not of the whole expression, so `a().b()` and `a()` get distinct keys. For callees with no name token (`(self.f)(x)`, `f()(x)`) it is the start of the argument list and `calleeName` is `""`.

## Enumeration

Every `call_expression` and `macro_invocation` inside a `function_item` body of every `.rs` file (excluding `.git`, `target`). `callerQualifiedName` = enclosing `mod::...::Type::fn` from the tree (impl type with generics stripped; trait name for trait items; nested fns as `outer::inner`).
Calls inside a macro `token_tree` are NOT enumerated (tree-sitter does not parse them as expressions). They are counted as `hiddenInMacro` heuristically: an identifier followed by a parenthesised token tree, or by `!` + token tree, inside any macro token tree in a fn body. Keywords such as `if (` can inflate this count slightly; it is a coverage caveat, not a site count.

## Categories and tie-breaks (purely syntactic; each site gets exactly one)

1. `macro_invocation` -> `macro-invocation`.
2. Method call (`recv.name(..)`, also `recv.name::<T>(..)`; method turbofish is classified by receiver, not `path-generic`):
   `self` -> `self-method`; `self.a.b...` (field chain rooted at `self`) -> `field-method`; identifier that is a parameter of the innermost enclosing fn -> `param-method`; identifier bound by a `let` in that fn -> `local-method`; everything else (call results, `for`/`match`/closure bindings, statics) -> `chained-method`.
   Tie-break: a parameter shadowed by a later `let` stays `param-method` (listed order wins). `let`s in nested fns do not leak outward.
3. Path/identifier call, first match wins:
   - path starts with a bracketed type `<T as Tr>::m` / `<T>::m` (even with turbofish) -> `qualified-trait`
   - turbofish anywhere (`f::<T>()`, `Vec::<T>::new()`, `Self::f::<T>()`) -> `path-generic` (beats the Self/Type/module shape)
   - callee name starts uppercase (`Some(x)`, `Foo(x)`, `Enum::Variant(x)`) -> `bare-closure-or-ctor` (beats `assoc-Type`)
   - path's last qualifier is `Self` -> `assoc-Self`; starts uppercase (`Type::f`, `io::Error::new`) -> `assoc-Type`; otherwise (`a::b::f`, `crate::`, `self::`, `super::`) -> `path-module`
   - lowercase bare identifier that is a param or `let`-bound name of the enclosing fn (calling a local closure) -> `bare-closure-or-ctor`; other lowercase bare identifier -> `bare-fn`
   - any other callee expression (`(self.f)(x)`, `f()(x)`, `xs[0](x)`) -> `bare-closure-or-ctor`
     Counts of all categories sum to the per-repo total (asserted by tests and at runtime).

## Split rule (fixed before labelling)

`split = "dev"` if the first 4 hex digits of `sha1("<repo>:<file>:<line>:<col>")` as an integer `% 10 < 6`, else `"held-out"`. `file` is repo-relative with `/`. Resolver iteration may look at `dev` failures only; `held-out` is measured once at the end and reported separately.

## Sampling

Per repo, per category: `quota = count` if `count <= 3`, else `min(5, max(1, round(30 * count / repoTotal)))`; take the first `quota` sites ordered by `sha1("<repo>:<file>:<line>:<col>")` ascending. Output order: repo, category (schema order), hash order.

## Freeze rule

After the ground truth and sample are committed they change only via `CORRECTIONS.md` (date, entry id, old -> new, evidence, who/how found), never silently.

## Labelling rules

- `target.line` is required for kind `resolved`; the evaluator matches by (file, simple name, line), not qualifiedName text. It is the 1-based line of the first token of the item itself (`pub`/`fn`/`struct`/`enum`/`trait`/variant), NOT its attributes and NOT its doc comments; for a multi-line signature, the first line.
- `qualifiedName` format: `Type::method`, `Trait::method`, a free fn as its bare name, nested fn `outer::inner`, inline-`mod` prefix `m::f`; impl generics stripped; no crate-relative module prefix.
- `confidence` for `external` and `unresolvable` labels is `exact` by convention and is not scored.
- A target that exists in several `cfg` variants: label the definition matching a Unix host (or the cfg-neutral one) and say which variant in `why`.
- A call whose CALLED symbol is a std/core trait method (e.g. `Into::into`, `Iterator::map`, `Clone::clone`) is `external`, even if the trait machinery ends up invoking an in-checkout impl (e.g. a `From` impl).
- Callers in `tests/`, `examples/`, `src/bin/` and `#[cfg(test)]` modules are in scope; a call from them that reaches an item defined in the checkout is `resolved`.
- `why` text is documentation, not scored; factual errors in it are still corrected through `CORRECTIONS.md`.
- Macro invocation of a std/dependency macro: `external`. Invocation of a `macro_rules!` defined inside the checkout: `unresolvable`, with `why` naming the macro_rules location. Macro sites are scored separately (macro_unresolved_rate).

## Trait-candidate supplement (`sample-trait.json`)

Generated by `npx tsx benchmarks/rust-call-oracle.ts --supplement trait-candidates` (the default mode still writes only `sample.json`/`counts.json`, byte-identical). The stratified sample has no trait-declaration targets, so this supplement adds them. Selection, per repo:

1. Collect method names declared in in-repo `trait_item`s (`function_signature_item` and default `function_item`), recorded as `Trait::method`.
2. Take the oracle's enumerated call sites (never `macro-invocation`, never calls hidden in macro token trees) whose `calleeName` equals one of those names.
3. Drop any site already in `sample.json` (same repo/file/line/col).
4. Order by `sha1("<repo>:<file>:<line>:<col>")` ascending; take all if <= 12, else the first 12.
5. `split` by the same Split rule (same function as the main sampler).
   Entries carry the `sample.json` fields plus `"supplement": "trait-candidate"` and `"traitMethods"` (every in-repo `Trait::method` sharing the callee name). Matching is by name only, so some candidates call an unrelated same-named method (e.g. a `GitignoreBuilder::build`); labelling decides. Supplement entries are scored SEPARATELY from the headline sample and never mixed into its recall/precision.

## Evaluation script

`npx tsx benchmarks/v1.5-rust-semantic-calls.ts [--split dev|held-out|all] [--final] [--repo <id>] [--out <path>] [--json]`. Default `--split dev`. `held-out`/`all` are refused without `--final`; `--final` is refused with `--repo` and once the log holds a `completed` line; otherwise it logs `started` before indexing and `completed` on success (a crash leaves only `started`, which does not block a rerun). Dev runs write nothing into the repo (`--out` must be outside it). Checkouts are copied into the OS temp dir and indexed there (disk-space constraint); the frozen labels are hash-checked before scoring.

The single final run is `--final --split all --out benchmarks/results/v1.5-phase2-rust-semantic-calls.json`: its JSON holds the dev, held-out and pooled reports from one indexing pass, plus timings and the leakage checks. `--report <that json> [--notes <md>]` renders the sibling `.md` from the JSON only (no indexing, no log); `--notes` appends hand-written analysis under its own heading.
