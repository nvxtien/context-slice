## Failure attribution (spec §74)

Failures counted: anchored-unresolved imports, anchored imports resolved to a file the oracle disagrees with, `mod foo;` with no file, resolved-but-name-missing imports, and non-anchored imports marked external that name in-repo code. Rules are deterministic and applied in the order listed in the code:

| category | rule |
| --- | --- |
| PARSER | The importing file, or the file the oracle says is the target, has a tree-sitter syntax error (genuine grammar error) OR the adapter failed to parse / emptied the file (an adapter defect, e.g. tree-sitter input-size limit: no symbols/imports/exports although the text contains items; the indexer reports these as parseErrors). Both sub-kinds are in this bucket; file counts per sub-kind are in the coverage table. |
| CARGO_WORKSPACE_RESOLUTION | The file belongs to a crate root that is not src/lib.rs or src/main.rs (src/bin/*, tests/*, examples/*, build.rs, or an orphan such as a second crate outside src/), or a non-anchored import names the package's own lib crate but was classified external. |
| RUST_STATIC_LIMIT | The use sits inside an inline `mod x { }` body; or its path continues into an inline mod / item that has no file of its own; or the mod declaration is cfg-gated with no file. |
| MACRO_EXPANSION_LIMIT | The resolved file contains macro_rules!/an invocation mentioning the imported name and no symbol of that name exists. |
| MODULE_RESOLUTION | The independent oracle finds a file-backed module for the path, but the adapter's modulePathFor disagrees with the oracle module path of that file. |
| USE_RESOLUTION | The oracle finds the target module file and modulePathFor agrees with it, yet the adapter left the import unresolved / resolved it to a different file; or the name appears only inside a `use` group the parser skips (nested use groups); or a non-anchored path names a mod/item/imported name in scope in the same file but was marked external; or a top-level braced `use {a::b, c::d};` was parsed as one import whose module text is the whole group; or the path continues two or more segments past the last file-backed module. |
| UNKNOWN | FALLBACK: none of the rules above matched, including a resolved-name-missing case where the imported name does not appear anywhere in the resolved file's text (marked in the example detail). Reported unminimized; see UNKNOWN examples. |

## Findings

Disclosure: the attribution rules (including the emptied-file PARSER rule and the treatment of `examples/*.rs` as crate roots) were adjusted after inspecting the first run's data; the rule table above is the final one. Files with a tree-sitter syntax error: walkdir 0, mini-redis 0, ripgrep-ignore 0; files emptied by the adapter: walkdir 0, mini-redis 0, ripgrep-ignore 0.

Every disagreement (10 + 4) is a non-lib crate root (`src/bin/*`, `tests/*`, `examples/*`, `build.rs`); MODULE_RESOLUTION disagreements inside the lib/main crate tree: 0 + 0 + 0.
- **use_resolution_rate (anchored).** resolved: walkdir 12/12 (before 2/9), mini-redis 52/52, ripgrep-ignore 81/81. Agreement of the resolved file with the oracle: walkdir 12/12, mini-redis 52/52, ripgrep-ignore 81/81 (before 13/23 for ripgrep-ignore: wrong-file resolutions are gone).
- **reexport_resolution_rate.** Non-wildcard re-exports that reach a symbolId: walkdir 3/3, mini-redis 19/19, ripgrep-ignore 9/9 (before: walkdir 0/0, ripgrep-ignore 0/9). walkdir's export records exist now because its crate root `src/lib.rs` is no longer emptied.
- **Non-anchored imports** are mostly external and the Cargo.toml oracle backs that up (std-family + declared dependency: walkdir 63/63, mini-redis 119/137, ripgrep-ignore 106/111); the remainder are own-package crates (limitation b). Local-resolved non-anchored imports agree with the oracle 23/23 in mini-redis. The `neither` bucket (walkdir 0, mini-redis 5, ripgrep-ignore 0) holds paths whose first segment is bound in the same file: they are no longer called external, and stay unresolved.
- **Counts that grew or look worse, and why.** Failure totals per repo are walkdir 0, mini-redis 38, ripgrep-ignore 13 (before 7, 36, 23). The rise in mini-redis CARGO_WORKSPACE_RESOLUTION (11 -> 18) and ripgrep-ignore RUST_STATIC_LIMIT / name-missing (6 -> 8) is not a regression: nested groups such as `use mini_redis::{clients::Client, DEFAULT_PORT}` and the `mod tests` imports of previously emptied files (`incremental.rs`, `walk.rs`) are now parsed, so limitations that were invisible before are now counted. ## Defects found by this evaluation and their status

### (a) Production defects

1. **FIXED: files longer than 32768 characters were silently emptied.** `parseRust` passed a string to tree-sitter, which throws `Invalid argument` above ~32 KiB; the catch returned no records with `parseError: true`. Emptied before: walkdir `src/lib.rs` (42415 chars); ripgrep-ignore `crates/ignore/src/dir.rs` (58367 chars), `crates/ignore/src/incremental.rs` (48097 chars), `crates/ignore/src/walk.rs` (93443 chars). After: walkdir none; ripgrep-ignore none. `parseRust` now feeds tree-sitter through the callback form in 4096-char chunks (as the TypeScript and Python adapters already did). Consequences that disappeared: walkdir anchored unresolved 7 -> 0; ripgrep-ignore wrong-file anchored resolutions 10 -> 0; ripgrep-ignore re-exports without a symbolId 9 -> 0.
2. **OPEN: private `use` chains are not followed.** `mini-redis/src/lib.rs:41-50` has `use db::Db;`, `use parse::{Parse, ParseError};`, `use shutdown::Shutdown;` (non-`pub`, visible to descendants). Imports such as `use crate::{Connection, Db, Frame, Parse};` (`src/cmd/get.rs:1`) resolve to `src/lib.rs` but the imported name is not a symbol or export there: 20 such cases in mini-redis (precision proxy 73.33%). Only `pub use` creates an ExportRecord. File-level `resolvedFile` is correct; symbol-level chain following belongs to Phase 2 call resolution.
3. **FIXED: top-level braced `use { a::b, c::d };` was mis-parsed** as one external import whose module was the whole group text (`gitignore.rs:17`, `types.rs:89`, `examples/walk.rs:3` in ripgrep-ignore; class malformed-top-level-use-group 3 -> 0). `parseUseDeclaration` is now one recursive use-tree parser covering top-level lists, nested groups, `self` (with and without alias), wildcards inside groups and aliases; unknown node types emit nothing.
4. **FIXED: a non-anchored path whose first segment is bound locally was called an external crate** (`use Command::*;`, `use ParseError::EndOfStream;`, `use frame::Error::Incomplete;`; in-scope-local-item class 4 -> 0, unverified 1 -> 0). `resolveRustCalls` now passes the per-file set of bound names to `resolveRustModule`, which returns unresolved (not external) for such a path.
5. **Side note (not fixed, not in scope): resolution is skipped for a language with zero indexed symbols.** `src/indexer/index.ts` calls `adapter.resolveCalls` only when `context.symbols.length` is non-zero, so a Rust-only repository whose files declare nothing never gets `resolvedFile`/`externalPackage` on its imports. Not reachable in the three benchmark repositories.

### (b) Known, documented limitations (workspace / bin / inline-mod / `#[path]`)

- Every `src/bin/*.rs`, `tests/*.rs`, `examples/*.rs` and `build.rs` is its own crate root but gets a src-relative module path (mini-redis 10, ripgrep-ignore 4 files; e.g. `src/bin/cli.rs` -> [bin, cli]). Their imports of the package's own library (`use mini_redis::...`: 18 in mini-redis; 5 in ripgrep-ignore) are classified external although the crate is in the repository.
- `walkdir/walkdir-list/main.rs` is a second crate outside `src/` and stays an orphan.
- Imports inside inline `mod tests { use super::X; }` are resolved at file granularity: `crates/ignore/src/default_types.rs:350` `use super::DEFAULT_TYPES` resolves to `lib.rs` although `super` of the inline module is `default_types.rs` (8 cases in ripgrep-ignore, RUST_STATIC_LIMIT).
- `#[path]`, cfg-gated modules and macro-generated modules are not modelled; none of them occurred in these three repositories (skipped-path-attribute 0, missing-file declarations 0), so this benchmark says nothing about them.

### (c) Oracle limitations

- Crate roots are inferred from directory conventions, not from Cargo.toml `[[bin]]`/`[lib] path`; `examples/*.rs` was added to the plan's root list (Cargo treats them as crates).
- `targetContainsName` is a proxy: it checks symbols, exports and enum-variant text in the resolved file, so private-`use` names and items generated by macros count as "missing"; it is not ground truth.
- Attribution rules are heuristic text rules (see the table); an import inside an inline module or a function body is evaluated at file granularity.
- Cargo.toml dependency detection is line-based and ignores renames and workspace-inherited tables.
- Three repositories (one sparse workspace member) are a small sample; percentages on small denominators (walkdir: 9 anchored imports) are not statistically meaningful.
