# v1.6 — Go support, Phase 3a real-repo benchmark

Real-repo symbol, import, export-visibility, and call-extraction benchmark for
the Go adapter (`parseGo`), run against three pinned checkouts of varying scale:

| repo | scale | kind | symbols found / total | imports found / total | calls found / total |
|---|---|---|---|---|---|
| [pkg/errors](https://github.com/pkg/errors) | small | library (error-wrapping) | 21/21 | 2/2 | 4/4 |
| [spf13/cobra](https://github.com/spf13/cobra) | medium | library (CLI framework) | 12/12 | 3/3 | 3/3 |
| [go-chi/chi](https://github.com/go-chi/chi) | large | library (HTTP routing) | 13/13 | 3/3 | 4/4 |

**46/46 (100%)** of the hand-curated symbol oracle, **8/8 (100%)** of the
hand-curated import oracle, and **11/11 (100%)** of the hand-curated call
oracle were found.

Phase 1's symbol-kind coverage (functions, methods, structs/`class`, interfaces,
type aliases, top-level variables, struct fields) is unchanged and still at 100%
with no regressions. Phase 2 adds:

- **Export visibility**: every existing oracle entry now carries `exported: true`
  (each was already a capitalized, genuinely-exported identifier), and each repo
  gained one new `exported: false` entry for a real unexported identifier read
  directly from source — `callers` (pkg-errors/stack.go:163), `stripFlags`
  (cobra/command.go:674), `chain` (chi/chain.go:36). The comparison now checks
  `modifiers.includes("exported")` against the oracle's `exported` flag wherever
  it's specified.
- **Imports**: a new `imports` oracle map with 2-3 real, hand-verified import
  entries per repo — `fmt`/`io` (pkg-errors/errors.go), `context`/`errors`/`os`
  (cobra/command.go), `net/http`/`context`/`sync` (chi/chi.go, chi/mux.go). All are
  plain package imports, so the adapter emits `kind: "namespace"` for each, matched
  against `index.imports` by module + kind.

Every new entry was read directly from the checked-out source during this task's
own execution and confirmed to exist exactly as named/kinded before being added, so
this run hit 100% on both symbols and imports on the first pass with no adapter
fixes needed.

Phase 3a adds call-edge extraction (Task 1: `src/languages/go/parse.ts`,
`collectCalls`/`buildCallEdge`) and this benchmark's coverage of it (Task 2): a new
`calls` oracle map with 3-4 real call sites per repo, hand-read from the same
checkouts and chosen to exercise `calleeName`s the symbol/import oracles above
don't already name — a mix of direct calls, selector/method calls on a local
receiver, and package-qualified stdlib calls:

- **pkg-errors**: `fmt.Sprintf` (errors.go:114), `io.WriteString` (errors.go:131),
  `runtime.FuncForPC` (stack.go:24), `strings.LastIndex` (stack.go:173).
- **cobra**: `c.getOut(...)` (command.go:394), `c.mergePersistentFlags()`
  (command.go:678), `strings.HasPrefix` (command.go:691).
- **chi**: `mx.NotFoundHandler()` (mux.go:66), `mx.handle(...)` (mux.go:116),
  `strings.IndexAny` (mux.go:110), `strings.TrimLeft` (mux.go:111).

Each is matched against `index.calls` by `calleeName`, and by `receiverText` too
wherever the oracle entry specifies one (every entry here does, since all four
repos' sampled calls are selector calls on a receiver — pkg-errors has no bare
unqualified-function call site distinct from an already-tested symbol name). All
11 were found on the first run with no adapter fixes needed, and no existing
symbol/import oracle entry regressed.
