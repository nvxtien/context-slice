# v1.6 — Go support, Phase 1 real-repo benchmark

Real-repo symbol-extraction baseline for the new Go adapter (`parseGo`), run against
three pinned checkouts of varying scale:

| repo | scale | kind | found / total |
|---|---|---|---|
| [pkg/errors](https://github.com/pkg/errors) | small | library (error-wrapping) | 16/16 |
| [spf13/cobra](https://github.com/spf13/cobra) | medium | library (CLI framework) | 10/10 |
| [go-chi/chi](https://github.com/go-chi/chi) | large | library (HTTP routing) | 12/12 |

**38/38 (100%)** of the hand-curated oracle symbols were found. Each oracle entry was
read directly from the checked-out source (`errors.go`, `stack.go`, `go113.go` for
pkg-errors; `command.go` for cobra; `chain.go`, `mux.go`, `chi.go` for chi) and
confirmed to exist with the expected name and kind before being added, so this run
hit the acceptance bar on the first pass with no adapter fixes needed.

This is Phase 1's symbol-extraction-only baseline: functions, methods, structs
(`class`), interfaces, type aliases/defined types, and top-level variables. It does
not yet cover call-edge resolution or import tracking — those are later phases'
additions to this same benchmark file (`benchmarks/v1.6-go-support.ts`).
