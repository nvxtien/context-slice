# v1.5 Phase 1 — Fixes Found by the Real-Repository Evaluation

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Single task.

**Goal:** Fix the three production defects the real-repository evaluation exposed in the Rust adapter, prove each with regression tests, and re-run the evaluation to produce honest BEFORE/AFTER numbers.

**Evidence (from `benchmarks/results/v1.5-phase1-rust-real-repositories.md`, pinned repos walkdir / mini-redis / ripgrep `crates/ignore`):**
- **D1 — oversized files silently emptied.** `parseRust` calls `rustParser().parse(source)` with a string. tree-sitter's string overload throws `Invalid argument` above ~32 KiB (reproduced independently: 28,779 chars OK, 34,979 chars throws; passing a `bufferSize` option or the callback form works). `parseRust` catches the throw and returns zero symbols/imports, so real files such as walkdir `src/lib.rs` (42,415 chars) and ripgrep `dir.rs`/`incremental.rs`/`walk.rs` are indexed as empty. The TypeScript and Python adapters already avoid this by using the callback form `parser.parse((index) => ...)` (`src/languages/typescript/parse.ts:117`, `src/languages/python/parse.ts:87`). Phase 0's "large-file regression" test used only ~3 KB and could not catch it.
- **D2 — `use` trees are only partly parsed.** Top-level `use { a::b, c::d };` becomes one garbage external import (ripgrep `gitignore.rs:17`, `types.rs:89`); `self` inside a group (`use crate::frame::{self, Frame}`, mini-redis `connection.rs:88`) is dropped; nested groups are skipped by design (Phase 1 plan header) although real code uses them heavily.
- **D3 — locally bound first segments are labelled external.** `use Command::*;` where `Command` is an enum declared in the same file, and `use ParseError::EndOfStream;` where `ParseError` is imported by another `use` in the same file, get `externalPackage` set (mini-redis `cmd/mod.rs:96`, `cmd/set.rs:81`). A name already bound in the file is not an external crate.

Deliberately NOT fixed here (documented limitations, rulings in the ledger): private non-`pub` `use` chains are not followed to find where a name is defined (file-level `resolvedFile` is already correct; symbol-level chain following belongs to Phase 2 call resolution); `mod tests { use super::X }` resolves at file level, not inline-module level; `src/bin`, `tests/`, `examples/`, `build.rs` crate roots and workspace/crate-name (`mini_redis::`) resolution.

## Global Constraints
- Fixes must be GENERIC. No logic keyed on repository names, file names from the pinned repos, or expected counts (spec §60, §91, §70 leakage rule). A grep of `src/` for `walkdir|mini_redis|mini-redis|ripgrep` must stay empty.
- Java, TypeScript and Python code and their benchmarks must not change. Only `src/languages/rust/*`, tests, benchmark scripts/results, and docs.
- Conservative behaviour: when unsure, leave an import unresolved rather than guess (spec §13).
- Do not weaken or delete existing tests to make them pass. If an existing test's expectation encoded a now-fixed defect, change it only with an explicit note in the report.
- Commit messages: short, single-line, imperative, NO `Co-Authored-By`/author trailer.
- `.js`-suffixed ESM relative imports. Test runner: `npx tsx --test <file>`, files flat under `tests/`.
- Numbers in reports come from real runs only (regenerate with the scripts; never hand-edit results).

- [ ] **Step 1 (D1): failing tests first.** Add regression tests that FAIL on the current code: (a) `parseRust` on generated sources of 32,767 / 32,768 / 32,769 / 65,536 / 200,000 chars (many `pub fn`s) returns ALL symbols and `parseError === false`; (b) the same through `ProjectIndex.rebuild()` in a temp dir with the large file next to a small one (assert every symbol present, `summary.parseErrors === 0`); (c) a large source containing multi-byte UTF-8 characters (e.g. `é`, `日本語` in comments/strings) so the chunking is exercised on non-ASCII text; (d) a large file with a `use crate::x::Y;` near the END so imports beyond 32 KiB are found. - [ ] **Step 2 (D2): tree dump, then failing tests, then a general recursive use-tree parser.** First dump the REAL tree-sitter-rust 0.21.0 shapes with a throwaway script (scratchpad, not the repo) for: `use { a::b, c };`, `use a::{self, b};`, `use a::{self as x};`, `use a::{b::{c, d}, e};`, `use a::{b::*, c};`, `use a::{*};`, `use a::b as c;`, `use self::x;`, `pub use a::{b, c::d};`, `use ::std::x;` (leading `::`) and record what node types you see (`use_list`, `scoped_use_list`, `use_as_clause`, `use_wildcard`, `scoped_identifier`, `self`, `crate`, `super`, `identifier`, `metavariable`?). Do not assume; trust the dump. Then write failing tests, then replace the flat-group logic in `parseUseDeclaration` with a recursive `useTree(node, prefix)` that handles every shape above. Semantics (keep the existing `ImportRecord.module` invariant: "everything except the final imported-name segment"; single-segment case keeps `module === importedName`):
  - leaf path `p` under `prefix` -> one record for full path `[...prefix, ...p]`;
  - `as` alias -> `localName` is the alias;
  - `self` inside a list under prefix `[..., m]` imports the module `m` itself: `module = prefix.slice(0,-1).join("::")` (or `m` itself when the prefix has one segment), `importedName = m`, `localName = m` (or the alias for `self as x`);
  - wildcard under prefix + path -> `wildcard: true`, `module` = the full prefix path;
  - nested `scoped_use_list` -> recurse with the extended prefix; top-level `use_list` (no path) -> recurse items with an empty prefix;
  - any node type you do not understand -> emit nothing for that subtree (never garbage, never a guess).
  `pub use` -> `ExportRecord`s continue to be derived from the same records (verify nested/self/wildcard `pub use` work end to end). Existing tests must still pass unchanged (the old "nested groups are skipped" expectation, if a test encodes it, is exactly the defect being fixed — change it explicitly and say so).

- [ ] **Step 3 (D3): failing tests, then the fix.** Add `rebuild()`-level tests: (a) `enum Command {A,B}` + `use Command::*;` in the same file -> NOT `externalPackage`, `resolvedFile` undefined; (b) `use crate::parse::{Parse, ParseError};` then `use ParseError::EndOfStream;` in the same file -> the second is not external; (c) regression: `use serde::Serialize;` with no local `serde` binding is STILL `externalPackage: "serde"`; (d) a local binding in file A must not affect file B's identically named external import.
