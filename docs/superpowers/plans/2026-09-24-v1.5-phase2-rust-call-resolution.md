# v1.5 Phase 2 — Rust Call Extraction and Resolution, Measured on Real Repositories

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Each `### Task N` is one dispatch. **The brief for a task contains only that task's section — always also read this plan's header (everything above `### Task 1`).**

**Goal:** Extract Rust call sites, resolve them conservatively (exact only when deterministic; `probable` for trait-declared targets; otherwise unresolved), and measure semantic call recall/precision on the three pinned real repositories (walkdir, mini-redis, ripgrep `crates/ignore`) against an INDEPENDENT hand-derived ground truth that is frozen before any resolver code is written.

**Architecture:** (1) An oracle enumerates every call site with raw tree-sitter (never the adapter), samples a stratified deterministic set, and assigns each sample to a `dev` or `held-out` split by a hash rule fixed before labelling. (2) Ground truth is labelled by reading source only, one repo per task, then spot-verified by an independent reviewer, then FROZEN (committed) before implementation. (3) `parseRust` emits `CallEdge`s and additive symbol metadata (impl Self type/trait, declared field/parameter types). (4) `resolveRustCalls` resolves in Python's rule order (`src/languages/python/resolve.ts` `resolvePythonCalls`) adapted to Rust. (5) An evaluation script reports recall/precision/false-positive rate per category and per split, extraction coverage vs the oracle, failure attribution, and the trait-resolution breakdown; iteration uses `dev` only, `held-out` is measured once at the end and reported separately.

**Spec:** `docs/prompt/CONTEXTSLICE_V1.5_RUST_SUPPORT.md` §21-27 (self/associated/trait/fully-qualified calls, ambiguity), §28-29 (generic bounds as evidence), §33-35 (async/`?` need no special edge), §36 (macros structural only), §54 (stdlib = external), §70 (independent ground truth, no leakage), §71-74 (metrics, trait-resolution breakdown, failure attribution).

## Global Constraints
- **Independence / no leakage.** Ground-truth labellers and the call oracle must NOT run or import the indexer/adapter (`ProjectIndex`, `parseRust`, `resolveRust*`, `modulePathFor`), and must not read `benchmarks/results/*` or any file produced by the evaluation. Nothing under `src/` may mention `semantic-calls`, repo names (`walkdir`, `mini-redis`, `mini_redis`, `ripgrep`), or expected results (extend the existing check in `tests/safety.test.ts` if needed).
- **Freeze rule.** The ground-truth files and the sample/split are committed BEFORE any Task 6-8 source change. After freezing they may only change through the correction log (`benchmarks/rust-semantic-calls/CORRECTIONS.md`: date, entry id, old → new, evidence, who found it and how) — never silently, never to make a number look better.
- **Split rule.** `split = "dev"` if `sha1("<repo>:<file>:<line>:<col>")` first 4 hex digits as an integer `% 10 < 6`, else `"held-out"`. Computed by the sampler, not by labellers or the resolver author. Resolver iteration may look at `dev` failures only; the held-out split is measured ONCE at the end of Task 9 and is reported separately from `dev`. If the held-out number is worse than `dev`, report both plainly.
- **Conservative resolution (§26).** `exact` only when a single deterministic target exists; ambiguity → `unresolved`; a target reached only through a trait declaration/bound → `probable` with `resolutionKind: "interface"`. Never invent a bean-winner-style guess.
- **No new `ResolutionKind` values.** Use existing ones: `this-member`, `static`, `constructor`, `same-file`, `imported`, `aliased-import`, `namespace-import`, `declared-type`, `interface`, `external-package`, `unresolved`. Trait-vs-inherent and "why unresolved" go in `evidence` strings using stable prefixes (`trait:`, `inherent:`, `macro:`, `ambiguous:`, `no-type:`) so the evaluation can classify them. Additive optional fields on `SymbolMetadata` are allowed (precedent: `classMethod`/`staticMethod`); nothing else in `src/types/model.ts` changes.
- **Cache.** Any change to Rust parse output requires bumping `INDEX_VERSION` (`src/storage/sqlite.ts`) in the SAME task, with the guard described in Task 9. Never leave old caches reusable.
- Java, TypeScript, Python behaviour and benchmarks unchanged; `src/` changes only under `src/languages/rust/` plus the additive `SymbolMetadata` fields and the `INDEX_VERSION` bump.
- Numbers in reports come from real runs of scripts; never hand-edited. Failures/limitations are reported, not hidden.
- Commit messages: short, single-line, imperative, NO `Co-Authored-By`/author trailer. ESM `.js` imports, tests flat under `tests/`, run with `npx tsx --test`.
- Pinned repos: `benchmarks/rust-repositories.json` (walkdir `6fd031c8…`, mini-redis `3d93b42b…`, ripgrep `3fce3b5b…` sparse `crates/ignore`). `npm run benchmark:checkouts` fetches them into git-ignored `benchmarks/checkouts/` (network needed).

## Ground-truth schema (`benchmarks/rust-semantic-calls/<repo>.json`)
One JSON array per repo; entry keys are human-readable, never internal symbol ids:
`{ "repo", "file", "line", "col", "callerQualifiedName", "callText", "calleeName", "category", "split", "expected": { "kind": "resolved" | "external" | "unresolvable", "target"?: { "file", "qualifiedName", "kind": "fn" | "method" | "assoc-fn" | "trait-method-decl" | "struct" | "enum-variant" }, "confidence": "exact" | "probable", "why": "<one line of evidence from the source>" } }`.
`resolved` = the call statically targets a definition inside the indexed scope (for a method on a concretely known type: the impl method; through a generic bound / `dyn` / `impl Trait`: the trait method declaration with `probable`). `external` = std/dependency/prelude or another crate outside the sparse scope (`target` omitted). `unresolvable` = target exists only via macro expansion/derive/blanket impl that cannot be known statically (`target` omitted). Categories (assigned by the oracle syntactically): `self-method`, `field-method`, `param-method`, `local-method`, `chained-method`, `assoc-Self`, `assoc-Type`, `path-module`, `path-generic`, `bare-fn`, `bare-closure-or-ctor`, `qualified-trait`, `macro-invocation`.

### Task 6: Extract calls; additive symbol metadata (parse.ts)
Add `parseRust` call extraction (in `src/languages/rust/parse.ts` or a new sibling `calls.ts` if the file is getting unwieldy) producing `CallEdge`s: `callerId` = the enclosing function/method symbol id, `calleeName` = method/field name or last path segment, `receiverText` = `self`, `self.a.b` (dotted text, ≤ 3 levels) for method calls, or the path prefix (`Self`, `Type`, `a::b`) for scoped calls, `argumentCount`, `range`, `confidence: "unresolved"`, `resolutionKind: "unresolved"`, `evidence: []`. Handle `generic_function` (turbofish) wrappers, `bracketed_type`/`qualified_type` paths (`<T as Trait>::m` → prefix keeps `<T as Trait>`), `.await`/`?` (no special edge; the call is a child), parenthesised callee `(self.cb)(x)` (unresolved, evidence `no-type:`), and record `macro_invocation` as a `CallEdge` with `evidence: ["macro:<name>"]` (macro arguments are opaque; do not walk `token_tree`). Node types/fields were verified against tree-sitter-rust 0.21.0: `call_expression{function,arguments}`, `field_expression{value,field}`, `scoped_identifier{path,name}`, `generic_function{function,type_arguments}`, `macro_invocation{macro}`, `await_expression`, `try_expression` — dump real snippets again before relying on them. Add optional `SymbolMetadata` fields (additive): `implSelfType?: string` and `implTrait?: string` on impl symbols (base type name without generics/references), and `declaredTypes?: Record<string,string>` on struct symbols (field name → type text) and function/method symbols (parameter name → type text, including `self`'s enclosing type via `implSelfType`). Tests first (RED), on synthetic fixtures for every call form and every metadata field; verify `calls` are produced through `ProjectIndex.rebuild()` and survive a warm rebuild. Bump `INDEX_VERSION`. Do not resolve anything yet.

### Task 7: Resolution, part A — structural targets (resolve.ts)
In `resolveRustCalls`, after import/export resolution, resolve `CallEdge`s in this order (mirror the shape of `resolvePythonCalls`): (1) `macro:` edges stay unresolved with evidence; (2) `self.m()` — collect methods named `m` across ALL impl blocks whose `implSelfType` equals the enclosing impl's Self type (inherent and trait impls): exactly one → `exact`/`this-member` (`inherent:` or `trait:` evidence); several → `unresolved` with `ambiguous:` evidence listing count; inside a trait default method → the trait's declared `m` as `probable`/`interface`; (3) `Self::f()`/`Type::f()` associated functions — `Self` = enclosing impl Self type; `Type` resolved to a struct/enum/trait symbol via same-file symbols or the file's imports (Phase 1 resolution: `importedName`/`localName`/`resolvedFile`, aliases via `as`), then the same "collect across impl blocks" lookup; `Type::new()` style → `static` (kind `constructor` only when the target is a tuple-struct/variant constructor); (4) module paths `a::b::f()`, `crate::x::f()`, `super::f()`, `self::f()`, `alias::f()` — resolve the path prefix with the existing `resolveRustModule`/import graph, then a top-level `fn` named `f` in the resolved file (`imported`/`aliased-import`/`namespace-import`), following `pub use` chains with the existing `lookup`; (5) bare `f()` — nearest same-file/same-module `fn` (`same-file`), then an imported name (`imported`/`aliased-import`, honouring `use … as g`), then a tuple-struct/enum-variant constructor, then prelude/std names (`Some`, `Ok`, `Err`, `drop`, `Box::new`… → `external-package` with `externalPackage: "std"`); a local binding that shadows an imported/outer name (`let f = …; f()`) must NOT resolve to the outer `fn` (negative fixture, spec §78). Ambiguity anywhere → `unresolved`, never a guess. Tests first (RED): positive fixtures per rule AND the negative fixtures — ambiguous method across trait+inherent impl, glob-import collision, unresolved external crate, cfg-gated duplicate `fn`, local binding shadowing, macro-hidden call. `dev` split failures may be inspected; held-out must not be.

### Task 8: Resolution, part B — typed receivers, external classification, generic bounds
Extend resolution with minimal, syntactic receiver typing (no inference engine): receiver type from (a) a parameter's declared type (`declaredTypes`, stripping `&`, `&mut`, `Box<>`/`Arc<>`/`Rc<>` wrappers only when the wrapper's own method name is not the callee — otherwise leave unresolved), (b) `self.field` via the struct's `declaredTypes`, (c) `let x: T = …`, (d) `let x = Type::new(..)` / `let x = Type { .. }` when `x` is assigned exactly once (Python `bindingClass` rule) — then resolve `x.m()` with the Part A "collect across impl blocks" lookup → `declared-type`; a generic parameter `R: Trait` / `where R: Trait` / `impl Trait` / `dyn Trait` receiver → the trait's declared method as `probable`/`interface` (spec §29), never a concrete impl; std traits/types (`AsRef`, `Iterator`, `Vec`, `String`, `Option`, `Result`…) and names of types not defined in scope → `external-package`. A method call whose receiver type is unknown AND whose method name is defined by no symbol in the project → `external-package` (`externalPackage: "std-or-dependency"`, `probable`); if the name IS defined by one or more project methods and the receiver type is unknown → `unresolved` with `no-type:` evidence and the candidate count (spec §26). Tests first (RED) including negatives: two impls define `run` and receiver type unknown → unresolved; wrapper-method-vs-inner-method; `dyn Trait` → probable trait decl. Iterate on `dev` only.
