# v1.4 Phase 0 — Enterprise Semantic Architecture Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the framework-neutral enterprise-relation architecture (types, extractor registry, indexer wiring, planner wiring) that later phases (Spring MVC, transactions/async/events, JPA/Spring Data, Kafka, config, test linkage) plug into — with zero behavior change to existing Java/TypeScript/Python output, proven by replaying the current benchmarks/tests unchanged.

**Architecture:** `Java AST → Java structural model → enterprise semantic extractors → generic semantic relations → context planner`, per §5 of the spec. Extractors live under `src/languages/java/enterprise/` as one file per semantic family (empty registry in this phase — no family module exists yet). Relations are a new `EnterpriseRelation[]` array on `ProjectIndex`, kept fully separate from `SymbolRecord`/`CallEdge` so core indexing is untouched. The planner gains a new `CompositionReason` variant but nothing produces it yet — Phase 1 (Spring MVC) is the first family to populate the registry and exercise planner wiring end-to-end.

**Tech Stack:** TypeScript, existing regex-based `parseJava` (`src/parser/java-parser.ts`, no tree-sitter query changes), Node's built-in test runner via `tsx --test tests/**/*.test.ts` (see `package.json` `scripts.test` — **not** vitest/jest; tests use `import test from "node:test"` and `import assert from "node:assert/strict"`, live flat under `tests/*.test.ts`, not mirrored in subdirectories), existing `benchmarks/benchmark.ts` runner.

**Spec:** [docs/prompt/CONTEXTSLICE_V1.4_JAVA_ENTERPRISE_CONTEXT_SEMANTICS.md](../../prompt/CONTEXTSLICE_V1.4_JAVA_ENTERPRISE_CONTEXT_SEMANTICS.md) — this plan implements §1 (benchmark rule, partially: baseline capture), §3 (preserve Java baseline), §4 (preserve TypeScript regression), §5 (framework-neutral architecture), §6 (relation model), §44 (planner wiring as optional evidence), §55/§58 (metric/failure-attribution scaffolding).

- Java retrieval recall = 100%, Java required-fact recall = 100%, Java semantic call regression = none (§3) — verified by replay, not re-derived.
- TypeScript retrieval recall / required-fact recall / semantic call recall / semantic call precision = 100% (§4) — verified by replay.
- No framework-specific conditionals (`if annotation == "Transactional"`) in core planner code (§5) — this phase adds no such conditionals since no family is implemented yet, but the registry shape must make that pattern unnecessary later.
- Relations must carry: source symbol, target symbol/object when known, confidence, evidence, source location, estimated context value where useful (§6).

```typescript
// src/languages/java/enterprise/registry.ts
import type { SymbolRecord } from "../../../types/model.js";
import type { EnterpriseRelation } from "../../../types/enterprise.js";

export type EnterpriseExtractor = (
  symbols: SymbolRecord[],
  filePath: string,
  source: string,
) => EnterpriseRelation[];

let extractors: EnterpriseExtractor[] = [];

/** Called once per family module at import time, mirroring registerLanguage in languages/adapter.ts. */
export function registerEnterpriseExtractor(extractor: EnterpriseExtractor) {
  extractors.push(extractor);
}

/** Runs every registered family extractor over one file's symbols and unions the results. */
export function extractEnterpriseRelations(
  symbols: SymbolRecord[],
  filePath: string,
  source: string,
): EnterpriseRelation[] {
  return extractors.flatMap((extractor) => extractor(symbols, filePath, source));
}

/** Test-only: clears registrations between test files so registry state doesn't leak. */
export function __resetEnterpriseExtractorsForTests() {
  extractors = [];
}
```

```typescript
export class ProjectIndex {
  readonly root: string;
  symbols: SymbolRecord[] = [];
  calls: CallEdge[] = [];
  imports: ImportRecord[] = [];
  exports: ExportRecord[] = [];
  private hashes = new Map<string, IndexedFileRecord>();
  private readonly storage: IndexStorage;
  // ... constructor, files(), counts(), inspect() unchanged ...

  rebuild() {
    const started = Date.now();
    const files = this.files(this.root);
    const previous = this.storage.load();
    this.symbols = [];
    this.calls = [];
    this.imports = [];
    this.exports = [];
    this.hashes = new Map();
    let filesParsed = 0;
    let cacheHits = 0;
    let parseErrors = 0;
    for (const file of files) {
      const filePath = relative(this.root, file);
      const adapter = adapterFor(filePath);
      if (!adapter) continue;
      const source = readFileSync(file, "utf8");
      const hash = createHash("sha256").update(source).digest("hex");
      this.hashes.set(filePath, { hash, language: adapter.id });
      if (previous.files.get(filePath)?.hash === hash) {
        this.symbols.push(
          ...previous.symbols.filter((symbol) => symbol.filePath === filePath),
        );
        this.calls.push(
          ...previous.calls.filter((call) => call.filePath === filePath),
        );
        this.imports.push(
          ...previous.imports.filter((record) => record.filePath === filePath),
        );
        this.exports.push(
          ...previous.exports.filter((record) => record.filePath === filePath),
        );
        cacheHits++;
        continue;
      }
      const parsed = adapter.parse(filePath, source);
      this.symbols.push(...parsed.symbols);
      this.calls.push(...parsed.calls);
      this.imports.push(...parsed.imports);
      this.exports.push(...parsed.exports);
      if (parsed.parseError) parseErrors++;
      filesParsed++;
    }
    // ... resolveCalls loop, storage.save, return summary unchanged ...
  }
}
```

Note both branches (`continue` on cache hit, and the fresh-parse fallthrough) currently `push` this file's symbols into `this.symbols` before moving to the next file — there is no single "file symbols" local variable today. You must introduce one so extraction runs exactly once per file regardless of which branch ran, using the already-read `source` (available in both branches) and that file's own symbols only.
