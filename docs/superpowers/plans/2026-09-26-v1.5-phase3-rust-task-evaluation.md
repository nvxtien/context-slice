# v1.5 Phase 3 — Rust Task-Based Context Evaluation (retrieval, required facts, context reduction)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax. **A task's brief is its own section plus this header (everything above `### Task 1`).**

**Goal:** Measure whether the merged Rust adapter (Phases 0-2) actually gives a developer the right context for real tasks: for hand-written locate / explain / change / impact tasks on the three pinned Rust repositories, report required-fact recall, retrieval recall, context reduction vs a manual baseline, whole-file fallback, minimum sufficient budget, and performance — with failed facts attributed to a cause. Then fix only the adapter defects that repeat, and verify the product surface (CLI/MCP/mixed-language) works on Rust.

**Architecture:** Mirror the v1.3 Python evaluation (`benchmarks/v1.3-python-support.ts`, `benchmarks/developer-context.ts`): a task file with source-fragment required facts and a manual-baseline file are written from the source ONLY and frozen; a new harness `benchmarks/v1.5-rust-tasks.ts` builds a `ProjectIndex` per checkout, assembles context for each task's target through the same entry/selection path as the Python harness, sweeps token budgets, checks facts, and writes `benchmarks/results/v1.5-phase3-rust-tasks.{md,json}`. Measurement first (no `src/` change), then a bounded fix loop driven by the evidence, then product-surface tests.

**Tech Stack:** TypeScript (ESM, `.js` imports), `npx tsx --test`, existing `ProjectIndex`, `estimateTokens`, `calculateContextMetrics`, pinned checkouts from `benchmarks/rust-repositories.json`.

**Spec:** `docs/prompt/CONTEXTSLICE_V1.5_RUST_SUPPORT.md` — §64-66 (MCP/CLI/mixed-language), §69-71 (task categories, independent ground truth, mandatory metrics), §74 (failure attribution), §75-76 (rust-analyzer gate, no premature rust-analyzer), §80 (performance), §87 items 9-11, 13-16 (report sections). NOT in this phase: §41-46 Cargo/workspace, §56-58 composition/skeletons, §31-40 closures/macros/attributes/cfg, §47-53 tests/unsafe/lifetimes, §82-86 packaging/docs/version. Rationale: Phases 0-2 never measured task-level usefulness; this phase decides which of those deferred areas the evidence actually justifies (Phase 4 input).

## Global Constraints
- **Independence / no leakage (§70).** Task authors and the harness's ground truth must not run or import the indexer/adapter, and must not read any `benchmarks/results/*` or evaluation output when writing tasks. Nothing under `src/` may mention the task ids, `requiredFacts`, `rust-tasks`, `rust-manual-context`, or repo names (`walkdir`, `mini-redis`, `mini_redis`, `ripgrep`); extend the existing check in `tests/safety.test.ts`.
- **Freeze rule.** `benchmarks/rust-tasks.json` and `benchmarks/rust-manual-context.json` are committed (Task 1) BEFORE the harness exists and before any `src/` change. Afterwards they change only through `benchmarks/rust-semantic-calls/CORRECTIONS.md`-style entries in a new `benchmarks/rust-tasks-CORRECTIONS.md` (date, task id, old → new, evidence, how found). Never edit a task to make a number better.
- **Fix-loop rule.** Only a failure cause that (a) loses a required fact or misses the target and (b) appears in ≥2 tasks or ≥2 repositories is fixed (§75). One-off failures are reported, not fixed. No rust-analyzer, rustc, or Cargo execution (§76).
- **Cache.** Any change to Rust parse output bumps `INDEX_VERSION` (`src/storage/sqlite.ts`) in the same commit, with the snapshot guard already in `tests/rust-parse-snapshot.test.ts`.
- Java, TypeScript, Python behavior and benchmarks unchanged; `src/` changes only under `src/languages/rust/` (+ the `INDEX_VERSION` bump) unless a Task 4 finding proves otherwise.
- Numbers in reports come from real runs; never hand-edited. Failures and limitations are reported, not hidden. Small samples are labelled as such.
- Commit messages: short, single-line, imperative, NO `Co-Authored-By` trailer (repo memory rule, overrides default attribution). Tests flat under `tests/`.
- Checkouts: `npm run benchmark:checkouts` (network) into git-ignored `benchmarks/checkouts/`; never commit them. If a benchmark run touches `benchmarks/results/v1.2-context-composition.*` (timestamp churn), `git checkout --` it before committing.

## Review Focus
1. A `targetSymbol` that is ambiguous (same method name on several types, e.g. `new`, `fmt`, `next`) — the harness must resolve by qualified name and fail loudly, not pick the first match (Task 2 test).
2. A required-fact pattern that occurs only in a different file than the target (fact lives in a callee/trait) — attribution must say `NOT_SELECTED`, not `PRESERVED` (Task 2 test).
3. A task whose target is in a file the adapter parsed as empty/parse-error — must be reported as an adapter failure, not a retrieval miss (Task 2 test).
4. Zero-caller symbol for an `impact` task — impact context must not crash and required facts about callers must be reported missing, not vacuously satisfied (Task 2 test).
5. Mixed Java/TS/Python/Rust repository — symbol ids must not collide and Rust files must not break other languages' indexing (Task 4 test).

## Task set design (fixed here so Task 1 has no open choices)
- 15 tasks: 5 per repository (walkdir, mini-redis, ripgrep-ignore) — 2 explain, 1 locate, 1 change, 1 impact each. (No Git-diff category: Java/TS/Python harnesses evaluate diff through preview tests, not this script; §69's diff category is covered by Task 4's preview test.)
- Each task: `{ id, repository, category, task, targetSymbol, groundTruthFiles, groundTruth, requiredFacts[3-4], baselineFiles }`, identical schema to `benchmarks/python-tasks.json`. `requiredFacts[].verification` = `{ "type": "source-fragment", "patterns": [...] }`; every pattern must appear verbatim in the pinned source of a `groundTruthFiles` entry.
- `targetSymbol` is the qualified name as the adapter reports it for that item (author finds it by reading the source's `mod`/`impl` nesting, NOT by running the indexer; the harness verifies it in Task 2 and mismatches are fixed by a correction entry only when the qualified-name convention, not the task, was wrong).
- Categories: `explain` = behavior inside one function/impl; `locate` = where a behavior lives; `change` = what a developer must read to modify a behavior (target + direct callees); `impact` = what breaks if the target changes (direct callers). Impact/change facts must be checkable as source fragments in caller/callee files.
- Manual baseline = the files a careful developer would open (`benchmarks/rust-manual-context.json`, `{taskId, files[], reasoning{file: why}}`), chosen before looking at any tool output.

```ts
import assert from "node:assert/strict";
import { mkdirSync, mkdtempSync, writeFileSync } from "node:fs";
import { tmpdir } from "node:os";
import { join } from "node:path";
import test from "node:test";
import { ProjectIndex } from "../src/indexer/index.js";
import { attributeFact, resolveTarget } from "../benchmarks/v1.5-rust-tasks.js";

function fixture() {
  const root = mkdtempSync(join(tmpdir(), "cs-rust-tasks-"));
  mkdirSync(join(root, "src"));
  writeFileSync(join(root, "Cargo.toml"), '[package]\nname = "f"\nversion = "0.1.0"\n');
  writeFileSync(join(root, "src/lib.rs"), "pub mod a;\npub mod b;\n");
  writeFileSync(join(root, "src/a.rs"), "pub struct A;\nimpl A { pub fn new() -> A { A } pub fn run(&self) { helper(); } }\nfn helper() {}\n");
  writeFileSync(join(root, "src/b.rs"), "pub struct B;\nimpl B { pub fn new() -> B { B } }\n");
  const index = new ProjectIndex(root);
  index.rebuild();
  return index;
}
test("ambiguous short name fails loudly, qualified name resolves", () => {
  const index = fixture();
  assert.equal(resolveTarget(index, "new").error, "ambiguous");
  assert.equal(resolveTarget(index, "nope").error, "not-found");
  assert.ok(resolveTarget(index, "A.new", "src/a.rs").symbol);
});
test("fact present only in the unselected callee is NOT_SELECTED", () => {
  const index = fixture();
  const target = resolveTarget(index, "A.run", "src/a.rs").symbol;
  const fact = { id: "f", description: "", verification: { type: "source-fragment", patterns: ["fn helper() {}"] } };
  assert.equal(attributeFact(fact, { target, fileParsed: true, selectedText: "pub fn run(&self)", fullText: "pub fn run(&self) fn helper() {}", groundTruthText: "fn helper() {}", budget: 8, }), "NOT_SELECTED");
});
test("missing target and empty parse are adapter defects", () => {
  const fact = { id: "f", description: "", verification: { type: "source-fragment", patterns: ["x"] } };
  assert.equal(attributeFact(fact, { target: undefined, fileParsed: true, selectedText: "", fullText: "", groundTruthText: "x", budget: 8 }), "TARGET_NOT_FOUND");
  assert.equal(attributeFact(fact, { target: undefined, fileParsed: false, selectedText: "", fullText: "", groundTruthText: "x", budget: 8 }), "ADAPTER_EMPTY_FILE");
});
test("impact of a zero-caller symbol does not crash and never vacuously passes", () => {
  const index = fixture();
  const b = resolveTarget(index, "B.new", "src/b.rs").symbol!;
  assert.deepEqual(index.callers(b), []);
});
```
