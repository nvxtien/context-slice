# ContextSlice v0.6 Developer Context Efficiency Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the existing deterministic benchmark so it measures developer context efficiency, manual whole-file baselines, context composition, fallback behavior, context-window pressure, and bounded multi-step context reuse.

**Architecture:** Keep retrieval unchanged and add a benchmark-only evaluation layer. Load auditable manual baselines from JSON, build a normalized ContextSlice package from the existing index, calculate metrics with shared token estimation and required-fact checks, then generate versioned JSON and Markdown reports.

**Tech Stack:** TypeScript, Node test runner, `tsx`, existing `ProjectIndex`, deterministic token estimator, JSON/Markdown report generation.

**Spec:** `docs/prompt/CONTEXTSLICE_V0.6_DEVELOPER_CONTEXT_EFFICIENCY.md`

## Global Constraints

- Reuse the exact three pinned repositories and existing 15 real benchmark tasks.
- Keep required-fact recall and retrieval recall at 100%; retain failures in aggregates.
- Use the same token estimator for manual and ContextSlice modes and label estimates separately from unavailable telemetry.
- Do not add JDT/LSP, embeddings, vector databases, cloud services, multi-language support, UI, hidden LLM calls, or automatic editing.
- Keep manual baselines separate from ContextSlice retrieval logic and make them machine-readable/auditable.
- Use developer-facing terms such as context tokens, minimum sufficient context, whole-file fallback, and developer context.

## Review Focus

- A missing or invalid manual baseline file must fail clearly rather than silently produce a favorable reduction.
- A missing target symbol or missing checkout must remain represented in the aggregate and must not be treated as successful retrieval.
- Required facts must be checked against the exact context package supplied by each mode.
- Estimated token metrics must never be mixed with optional assistant telemetry.
- Multi-step duplicate context must be counted consistently when the same file or symbol is repeated.
