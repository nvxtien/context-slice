# v1.5 Phase 4 — Rust Import Context, Docs and Release Packaging Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **A task's brief is its own section plus this header (everything above `### Task 1`).**

**Goal:** Close the one evidence-backed gap Phase 3 left open (an import line outside any symbol's context), then ship the release-gating work the spec always required once behavior is evaluated: README/docs update, `docs/rust-support.md`, version bump to `1.5.0`, and a packaged clean-room Rust smoke test.

**Architecture:** (1) Rust's parser gains a synthetic per-file "module" symbol that owns top-level `use` declarations — the same pattern TypeScript's `parse.ts` already uses for top-level statements (`moduleSymbol`, `src/languages/typescript/parse.ts:137-160,797-819`) — so an import line becomes retrievable as a symbol's source. (2) A new, Rust-only composition step (`composeImportContext`, alongside the existing Java-only `javaFieldDeclarations` precedent in `src/planner/composition.ts`) attaches a caller/callee's file-level import block as bounded, deduped context, wired into `buildPreview` (`src/workflow/preview.ts`) and the Phase 3 harness. (3) Phase 3's report is regenerated to confirm the gate closes, with a Phase 2 regression check. (4) README, `docs/rust-support.md`, `CHANGELOG.md` and `package.json`'s version are updated to match every prior language doc's pattern (`docs/python-support.md`, `docs/typescript-support.md`, the `CHANGELOG.md` `1.1.0`-`1.3.0` entries). (5) `scripts/package-smoke-test.ts` gains a Rust clean-room pass mirroring its existing Java pass.

**Tech Stack:** TypeScript (ESM, `.js` imports), `npx tsx --test`, existing `ProjectIndex`/`buildPreview`, tree-sitter-rust (already a normal npm dependency — no `queries/rust/*.scm` exists or is needed, unlike Java).

**Spec:** `docs/prompt/CONTEXTSLICE_V1.5_RUST_SUPPORT.md` — §56-58 (composition, module skeleton — narrowly, the import-block case Phase 3 evidence justified), §82-83 (packaging, clean-room Rust smoke test), §84 (README), §85 (`docs/rust-support.md`), §86 (version `1.5.0`), §87 items 1-8 (report sections already covered by Phases 0-3's reports; this phase adds nothing new there). Phase 3→4 recommendation: `docs/superpowers/plans/2026-09-26-v1.5-phase3-phase4-recommendation.md`. NOT in this phase (no evidence, per the recommendation): Cargo/workspace resolution (§41-46), general composition skeletons beyond the one justified case (§57-58), closures/derive metadata (§31-40 beyond Phase 3's fixes), tests/unsafe/lifetimes (§47-53), rust-analyzer (§75-76 — explicitly not warranted, see the recommendation doc).

## Global Constraints
- **Evidence discipline.** The only new resolution/composition behavior in this phase is the import-context composer, justified by the single remaining Phase 3 gap (`ripgrep-ignore-is-hidden-path-impact` / `import`). Do not add anything else "while we're in there" — no Cargo parsing, no closures, no new call-resolution rules.
- **Language isolation.** The new composer is Rust-only, gated the same way `javaFieldDeclarations` (`src/planner/composition.ts`) is Java-only (`if (parent.language !== "java") return [];`). Java, TypeScript and Python behavior, benchmarks, and reports must not change — verify by running `npm run benchmark:v04` (Java+TS regression numbers) unaffected, or, if that's too slow, by a scoped test proving the composer returns `[]` for non-Rust targets.
- **Cache.** The new synthetic symbol changes Rust parse output → bump `INDEX_VERSION` in `src/storage/sqlite.ts` in the SAME commit as the `parse.ts` change, and update `tests/fixtures/rust-parse-snapshot.json` only through the existing guard in `tests/rust-parse-snapshot.test.ts`.
- **No rustc/rust-analyzer/Cargo execution.** Structural, Tree-sitter-only, per spec §5 and §76.
- Numbers in reports come from real runs of scripts; never hand-edited.
- Commit messages: short, single-line, imperative, NO `Co-Authored-By`/author trailer (repo memory rule). ESM `.js` imports, tests flat under `tests/`, run with `npx tsx --test`.
- **Do not modify** `benchmarks/rust-tasks.json` or `benchmarks/rust-manual-context.json` (frozen in Phase 3) — only the derived report files regenerate.
- **Publication.** `npm pack`/`npm ci`/isolated-install verification only. No `npm publish`, no Git tag, no GitHub Release, no version-control push beyond this plan's own commits (matches every prior "(unpublished)" `CHANGELOG.md` entry).

## Review Focus
1. The synthetic import symbol must never collide with a real declared symbol's id or search ranking (TypeScript's precedent names it after the file path specifically to avoid this) — test a file whose only top-level item is literally named the same as the module symbol's synthetic name pattern.
2. A file with zero top-level `use` declarations (e.g. `main.rs` with only `fn main()`) must not gain a synthetic symbol with empty, useless source — verify no symbol is added when there is nothing to hold.
3. The import composer must be budget-bounded and deduped: a target with five callers all in the same file must attach that file's import block once, not five times, and must never exceed the composition budget share.
4. Re-running the Phase 3 harness after this phase's fix must not silently change any OTHER task's fact recall (regression-by-omission) — the Before/After table already built in Phase 3 covers this; extend it, don't bypass it.
5. `npm pack`'s tarball must still include everything the Rust adapter needs at runtime (tree-sitter-rust is a normal `dependencies` entry, so this is really "did the Rust smoke pass actually exercise indexing, not just CLI help text") — the new Rust smoke section must assert on real Rust symbol content, not just exit codes.

**Interfaces:**

- Produces: for a Rust file with at least one top-level `use_declaration`, one additional `SymbolRecord` in the returned `symbols` array:
  - `id`: `` `${filePath}::module::${filePath}` `` (identical naming convention to TypeScript's `moduleSymbol.id`, `src/languages/typescript/parse.ts:143`)
  - `kind: "namespace"`
  - `name: filePath`, `qualifiedName: filePath`
  - `metadata: { moduleScope: true }`
  - `source`: the joined `.text` of every direct `use_declaration` child of `tree.rootNode`, each on its own line, in source order
  - no `parentId`, no `bodyRange`
  Later tasks find this symbol by `kind === "namespace" && metadata?.moduleScope === true && filePath === <the file in question>`.

```ts
import assert from "node:assert/strict";
import test from "node:test";
import { parseRust } from "../src/languages/rust/parse.js";

test("a file with top-level use declarations gets a synthetic import symbol", () => {
  const source = [
    "use std::fs;",
    "use crate::util::helper;",
    "",
    "pub fn run() {",
    "    fs::read_to_string(\"x\").ok();",
    "}",
  ].join("\n");
  const parsed = parseRust("src/lib.rs", source);
  const moduleSymbol = parsed.symbols.find(
    (s) => s.kind === "namespace" && s.metadata?.moduleScope === true,
  );
  assert.ok(moduleSymbol, "expected a synthetic module/import symbol");
  assert.equal(moduleSymbol!.filePath, "src/lib.rs");
  assert.equal(moduleSymbol!.id, "src/lib.rs::module::src/lib.rs");
  assert.match(moduleSymbol!.source, /use std::fs;/);
  assert.match(moduleSymbol!.source, /use crate::util::helper;/);
  // The real function symbol must be unaffected and still present.
  assert.ok(parsed.symbols.some((s) => s.kind === "function" && s.name === "run"));
});

test("a file with no top-level use declarations gets no synthetic symbol", () => {
  const source = "pub fn main() {\n    println!(\"hi\");\n}\n";
  const parsed = parseRust("src/main.rs", source);
  assert.equal(
    parsed.symbols.some((s) => s.kind === "namespace" && s.metadata?.moduleScope === true),
    false,
  );
});

test("a use declaration inside a nested inline mod is not pulled into the file-level symbol", () => {
  const source = [
    "use std::fs;",
    "",
    "mod inner {",
    "    use std::io;",
    "    pub fn f() {}",
    "}",
  ].join("\n");
  const parsed = parseRust("src/lib.rs", source);
  const moduleSymbol = parsed.symbols.find(
    (s) => s.kind === "namespace" && s.metadata?.moduleScope === true,
  );
  assert.ok(moduleSymbol);
  assert.match(moduleSymbol!.source, /use std::fs;/);
  assert.doesNotMatch(moduleSymbol!.source, /use std::io;/);
});
```
