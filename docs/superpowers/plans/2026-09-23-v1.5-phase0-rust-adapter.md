# v1.5 Phase 0 — Rust Adapter Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up a real, tree-sitter-based Rust language adapter that indexes top-level Rust items (functions, structs, enums, traits, impls, modules, consts, statics, type aliases) as `SymbolRecord`s, registered into ContextSlice's existing language-adapter system — with zero call/import resolution yet (that's Phase 1+) and zero regression to Java/TypeScript/Python.

**Architecture:** Mirrors the existing TypeScript and Python adapters exactly: `src/languages/rust/{index,parse,resolve}.ts`, using `tree-sitter` + `tree-sitter-rust` to build a real syntax tree (not regex, matching spec's "Tree-sitter first" mandate). `parse.ts` walks the tree recursively to build `SymbolRecord`s with proper parent/child nesting (module → impl/trait → method). `resolve.ts` is a no-op stub in this phase (`resolveCalls` does nothing — no call edges are produced yet, since Rust source has no `CallEdge` extraction logic until a later phase). `index.ts` assembles the `LanguageAdapter` and self-registers via `registerLanguage`, then is imported for its side effect from `src/indexer/index.ts`, exactly like `java.js`/`typescript/index.js`/`python/index.js` already are.

**Tech Stack:** TypeScript, `tree-sitter` (already a dependency) + `tree-sitter-rust@^0.24.0` (new dependency, confirmed to exist on npm and its grammar verified directly against `node-types.json` — see field names cited in Task 2), Node's built-in test runner via `npx tsx --test <file>` (this repo does NOT use vitest/jest — confirm with `cat package.json | grep -A3 '"scripts"'` if in doubt).

**Spec:** [docs/prompt/CONTEXTSLICE_V1.5_RUST_SUPPORT.md](../../prompt/CONTEXTSLICE_V1.5_RUST_SUPPORT.md) — this plan implements a narrow slice: §1 (benchmark rule, partial: baseline capture), §2 (primary objective, partial), §3 (preserve existing languages), §4 (language adapter), §5 (tree-sitter first), §6 (file detection), §7 (Rust symbols — functions/structs/enums/traits/impls/modules/const/static/type-alias only; macros/closures/tests deferred), §8 (functions, partial: name/params/return-type/async/visibility captured; generics/where-clause deferred to a later phase), §9 (modules), §16-20 (structs/tuple-structs/enums/traits/impls). Explicitly OUT of scope for this phase (deferred to Phase 1+): §11-15 (use/crate/self/super/glob/re-export resolution), §21-30 (call resolution, generics-as-evidence, associated types), §31-40 (closures, async/await as calls, macros, attributes, cfg), §41-46 (Cargo.toml/workspace), §47-53 (tests, unsafe, lifetimes), §54-63 (stdlib calls, composition, skeletons, path resolution, multi-binary, build.rs, includes), §67+ (real-repo benchmarks, metrics, packaging, docs, version bump).

```typescript
// src/languages/rust/parse.ts
import Parser from "tree-sitter";
import Rust from "tree-sitter-rust";
import type { SourceRange } from "../../types/model.js";

export type Node = Parser.SyntaxNode;

export const LANGUAGE_ID = "rust";

let parser: Parser | undefined;
export function rustParser() {
  if (!parser) {
    parser = new Parser();
    parser.setLanguage(Rust as any);
  }
  return parser;
}

export const range = (node: Node): SourceRange => ({
  startLine: node.startPosition.row + 1,
  startColumn: node.startPosition.column,
  endLine: node.endPosition.row + 1,
  endColumn: node.endPosition.column,
});
export const field = (node: Node, name: string) => node.childForFieldName(name);
export const text = (node: Node | null | undefined) => node?.text ?? "";
```

Consumed by Task 3's adapter wiring.

This is the substantial task. The tree-sitter-rust grammar's node types and field names below were verified directly against the installed package's `node-types.json` (not guessed) — trust them exactly as given:

| Item | Node type | Fields |
|------|-----------|--------|
| Function | `function_item` | `name`, `parameters`, `return_type`, `body`, `type_parameters` |
| Struct | `struct_item` | `name`, `body`, `type_parameters` |
| Enum | `enum_item` | `name`, `body`, `type_parameters` |
| Trait | `trait_item` | `name`, `body`, `bounds`, `type_parameters` |
| Impl block | `impl_item` | `type` (the Self type), `trait` (present only for `impl Trait for Type`), `body`, `type_parameters` |
| Module | `mod_item` | `name`, `body` (absent for `mod foo;`, present for `mod foo { ... }`) |
| Const | `const_item` | `name`, `type`, `value` |
| Static | `static_item` | `name`, `type`, `value` |
| Type alias | `type_item` | `name`, `type`, `type_parameters` |
| Trait method (no body) | `function_signature_item` | `name`, `parameters`, `return_type`, `type_parameters` (appears inside a `trait_item`'s `body` for methods with no default implementation) |

Visibility: a `pub` modifier appears as a `visibility_modifier` child node (check `node.children.some(c => c.type === "visibility_modifier")`) on the item node itself — it is NOT a named field, so use `.children`, not `field()`.

Async: an async function has an `async` child token (check `node.children.some(c => c.type === "async")`) — also not a named field.

```typescript
import type {
  ExportRecord,
  ImportRecord,
  SymbolKind,
  SymbolRecord,
} from "../../types/model.js";
import type { ParsedFile } from "../adapter.js";

const ITEM_TYPES = new Set([
  "function_item",
  "function_signature_item",
  "struct_item",
  "enum_item",
  "trait_item",
  "impl_item",
  "mod_item",
  "const_item",
  "static_item",
  "type_item",
]);

// SymbolKind (src/types/model.ts:3-17) has no "struct" or "trait" member —
// verified directly against the live type before writing this plan, do not
// add "struct"/"trait" as kind values, tsc will reject them.
const KIND_BY_NODE_TYPE: Record<string, SymbolKind> = {
  function_item: "function",
  function_signature_item: "function",
  struct_item: "class", // closest existing kind for a data-bearing named type
  enum_item: "enum",
  trait_item: "interface", // closest existing kind: a trait is a behavioral contract
  impl_item: "type", // impl blocks are containers, not themselves a named declaration; shares "type" with type aliases deliberately, revisit if this causes ambiguity in a later phase
  mod_item: "namespace",
  const_item: "variable",
  static_item: "variable",
  type_item: "type",
};

const isPub = (node: Node) =>
  node.children.some((child) => child.type === "visibility_modifier");
const isAsync = (node: Node) =>
  node.children.some((child) => child.type === "async");

function canonicalId(filePath: string, chain: string[], kind: SymbolKind, name: string) {
  return [filePath, ...chain, kind, name].join("::");
}

/** impl blocks have no `name` field — label them by their Self type (+ trait, if any). */
function implLabel(node: Node): string {
  const selfType = text(field(node, "type"));
  const traitNode = field(node, "trait");
  return traitNode ? `impl ${text(traitNode)} for ${selfType}` : `impl ${selfType}`;
}

function itemName(node: Node): string {
  if (node.type === "impl_item") return implLabel(node);
  return text(field(node, "name"));
}

export function parseRust(filePath: string, source: string): ParsedFile {
  const symbols: SymbolRecord[] = [];
  let parseError = false;
  let tree: Parser.Tree;
  try {
    tree = rustParser().parse(source);
    parseError = tree.rootNode.hasError;
  } catch {
    return { symbols: [], calls: [], imports: [], exports: [], parseError: true };
  }

  function walk(node: Node, parent: SymbolRecord | undefined, chain: string[]) {
    for (const child of node.namedChildren) {
      if (!ITEM_TYPES.has(child.type)) {
        // Not a top-level item itself, but it may contain one (e.g. a source_file
        // wraps everything; an impl/trait/mod body wraps its members directly, so
        // this branch mainly matters for source_file's implicit top level).
        walk(child, parent, chain);
        continue;
      }
      const name = itemName(child);
      if (!name) continue;
      const kind = KIND_BY_NODE_TYPE[child.type];
      const id = canonicalId(filePath, chain, kind, name);
      const modifiers = isPub(child) ? ["pub"] : [];
      const symbol: SymbolRecord = {
        id,
        language: LANGUAGE_ID,
        kind,
        name,
        qualifiedName: [...chain, name].join("::"),
        canonicalIdentity: id,
        signature: child.text.split("\n")[0].trim(),
        filePath,
        range: range(child),
        bodyRange: field(child, "body") ? range(field(child, "body")!) : undefined,
        parentId: parent?.id,
        annotations: [],
        modifiers,
        metadata:
          child.type === "function_item" && isAsync(child)
            ? { async: true }
            : undefined,
        source: child.text,
        body: field(child, "body")?.text,
      };
      symbols.push(symbol);
      const body = field(child, "body");
      if (body) walk(body, symbol, [...chain, name]);
    }
  }

  walk(tree.rootNode, undefined, []);
  const imports: ImportRecord[] = [];
  const exports: ExportRecord[] = [];
  return { symbols, calls: [], imports, exports, parseError };
}
```
